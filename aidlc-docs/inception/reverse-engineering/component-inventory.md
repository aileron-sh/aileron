A note on the upstream template: it assumes a multi-package workspace (CDK stacks, service packages,
shared models). Aileron is one distributable package, so "package" is read as "module" below and the
infrastructure and shared-package sections are recorded as empty rather than invented.

## Application Packages

One distributable package: **`aileron`** (`src/aileron/`) — flight recorder for AI agents; library,
console script, and MCP proxy in one wheel.

Modules within it, grouped by role:

**Core integrity**
- `events` — canonical JSON, event construction, hashing, validation. Leaf; no intra-package imports.
- `chainlog` — append-only hash-chained journal, digest-only stripping, total verifier.
- `signing` — Ed25519 keypair, chained checkpoints over a prefix, offline verification, unauthenticated cross-check.

**Decision**
- `policy` — YAML rule loading and allow/alert/block decisions.
- `detect` — rolling behavioural baselines; advisory flags only. Leaf; no intra-package imports.

**Capture paths**
- `sdk` — `@track` decorator and `track_agent` session; in-process, bypassable by design.
- `proxy` — MCP stdio mediation; out-of-process, unskippable, fail-closed.

**Read-only consumers**
- `otel` — OpenTelemetry GenAI-aligned span and OTLP/JSON export.
- `report` — single-file HTML incident report with verification badge.

**Interface and packaging**
- `cli` — ten subcommands, exit-code policy, key-fingerprint disclosure, scripted demo.
- `__init__` — lazy public façade, `__version__`, `bundled_rules_dir()`.

## Infrastructure Packages

None. There is no CDK, Terraform, CloudFormation, Dockerfile, or deployment script in the
repository. The only automation is GitHub Actions:

- `.github/workflows/ci.yml` — test matrix, Ubuntu + macOS × Python 3.10–3.13, `fail-fast: false`.
- `.github/workflows/benchmark.yml` — proxy-overhead regression guard, path-filtered to code that
  can affect latency, fails at >2× baseline median on two consecutive runs.
- `.github/workflows/release.yml` — test → build → publish to PyPI via trusted publishing (OIDC).

This absence is a finding, not an omission: it is the reason most resiliency-extension rules resolve
to N/A, and it is why "Operations" for this project means release engineering rather than deployment.

## Test Packages

No separate test package; `tests/` is a flat directory of unit and integration tests, one module per
source module, each inserting `../src` on `sys.path`. There is no `conftest.py`.

- Unit: `test_events.py`, `test_chainlog.py`, `test_signing.py`, `test_policy.py`, `test_detect.py`,
  `test_otel.py`, `test_report.py`.
- Integration (spawns real subprocesses or drives the real entry point): `test_proxy.py` (real MCP
  child servers over pipes), `test_cli.py` (calls `main(argv)` directly).
- Mixed: `test_sdk.py` (in-process, but exercises journal, policy, and baseline together).

## Supporting Scripts and Examples
