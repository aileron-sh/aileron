# Code Quality Assessment

Generated by AI-DLC Reverse Engineering against git `6c09efd` (Aileron 0.1.3), 2026-08-12.

Overall judgement: this is a well-built codebase for its age. The security invariants are unusually
deliberate, the verifier is written to be total rather than merely correct, and several commits in
the history are genuine hardening fixes rather than features. The weaknesses are concentrated in
three places — documentation drift, a set of intentional invariants that no test pins down, and one
file that has become a coupling hotspot.

## Test Coverage

- **Overall**: Good by count and structure, uneven by risk. 117 test functions across 10 modules,
  2,083 lines of test code against 2,625 lines of source — a ratio most projects this age do not
  reach. One test module per source module, matching `SPEC.md`'s ownership model.
- **Unit Tests**: Present for every module. `test_policy.py` (20 defs, 25 collected) and
  `test_chainlog.py` / `test_signing.py` (13 each) are the strongest; `test_events.py` has 8 for a
  branch-heavy `validate` that is exercised mostly through one omnibus test.
- **Integration Tests**: Real ones. `test_proxy.py` spawns actual subprocess children over pipes
  rather than mocking the transport, and `test_cli.py` drives `main(argv)` directly. That is the
  right call for a mediation tool: the bugs live in framing and process lifecycle.
- **Coverage measurement**: **none configured.** No `coverage`/`pytest-cov` in the dev extra and no
  coverage job in CI, so the numbers above are structural, not measured. The percentage is unknown.

### Untested invariants — the most actionable finding

Each item below is a behaviour the code deliberately guarantees, with no test asserting it. A grep of
`tests/` for `record_failed`, `MAX_PENDING`, `_canonical_wire`, and `fingerprint` returns nothing.
`Content-Length` does appear throughout `test_proxy.py`, but only for the duplicate, non-numeric, and
oversized cases — nothing exercises the `_HEADER_RE` field-name check.

1. **"Forward what we policed, not the peer's bytes"** (`proxy._canonical_wire`, applied both
   directions). This is the fix the 0.1.2 changelog itself calls *critical*, and the existing framing
   round-trip tests pass whether or not it is present. Highest-value gap in the repo.
2. **Malformed-header rejection** (`proxy._HEADER_RE`, RFC 7230 field-name check) — the
   header-smuggling defence.
3. **All `record_failed` paths** — child framing error, journal write failure, reader-thread abort,
   and the re-check immediately before forwarding that refuses with `-32000`.
4. **`MAX_PENDING` overflow** and its `aileron-pending-limit` pseudo-rule.
5. **Non-mapping `params` guard** and the **non-scalar response-`id` guard** in the proxy.
6. **Proxy JSON-RPC error redaction** (reducing error `data` to `{code, digest}`).
7. **`verify-checkpoint` key disclosure** — the printed absolute path, the `sha256:` fingerprint, and
   the stderr warning when the key was auto-resolved beside the log. This is the trust-anchor
   disclosure; if it silently regressed, verification would look identical while meaning less.

### Well-covered invariants (for contrast)

Digest-only capture including the two tests that assert `"rm -rf"` never reaches the journal file;
blocked calls still journaled with the function never invoked; batch and id-less `tools/call` unable
to bypass a block; blocked batches answering every id while blaming the right one; in-flight calls
drained as `status="error"` on child death; duplicate in-flight JSON-RPC ids journaled rather than
erased; byte-exact canonical encoding catching duplicate JSON keys; nothing chaining onto a broken
line; checkpoint prefix semantics, reordering, and intermediate deletion; refusal to sign a broken or
empty chain; key files created `0o600` with `O_NOFOLLOW`; HTML escaping including the badge fields;
`verify` remaining total on invalid UTF-8 and non-object lines; and the 0.1.3 checkpoint cross-check
distinguishing truncation from rewriting.

## Code Quality Indicators

- **Linting**: **not configured.** No ruff, flake8, black, isort, or pre-commit config anywhere.
- **Type checking**: **not configured**, yet the package ships `py.typed`. Downstream users receive
  type promises that CI never verifies — the clearest single gap relative to what is advertised.
- **Code Style**: consistent in practice. Uniform annotations, private helpers prefixed `_`,
  dataclasses for value types, docstrings on the non-obvious modules. Consistency is currently
  maintained by discipline rather than by tooling.
- **Documentation**: good at the top level and unusually honest — the README has an explicit "Honest
  limitations" section that matches the code, and the benchmark methodology is reproducible by one
  command with the caveats stated plainly. The weak point is `SPEC.md` (below).
- **Commit hygiene**: strong. Prefixed, single-purpose commits (`security:`, `perf:`, `docs:`,
  `bench:`, `ci:`, `release:`) with security fixes separated from features.

## Technical Debt

### 1. `SPEC.md` has drifted from the code while claiming to be the single source of truth
Four concrete divergences: canonical JSON is documented as `ensure_ascii=False` but implemented as
`ensure_ascii=True` with `allow_nan=False` (the 0.1.1 breaking change); the version is stated as
`0.1.0` against an actual `0.1.3`; the checkpoint structure omits `index` and `prev_checkpoint_hash`,
which are exactly the fields that make reordering and deletion detectable; and `detect.Baseline` is
described as a per-tool *hourly* rate where the implementation uses a 60-second trailing window.
Also missing entirely: `check_against_checkpoints`, `--skip-checkpoint-check`, `bundled_rules_dir`,
`MAX_PENDING`, and `record_failed`.

This is the highest-priority debt item, because every future AI-DLC session will read `SPEC.md` as
authoritative context. A stale spec in a context-engineered workflow is worse than no spec.

### 2. `cli.py` is the coupling hotspot
461 lines holding `_build_parser`, `_DISPATCH`, ten `_cmd_*` handlers, and a ~100-line `_cmd_demo`
with its own scripted behaviour. Nine of the sixteen features touch it — eight besides the CLI unit itself. `main()` also special-cases
the `rules` group outside `_DISPATCH` (`# only 'test' exists today`), so adding a second `rules`
subcommand means editing dispatch as well as the parser. Any two parallel units that add a
subcommand will collide here.

### 3. `action: allow` is accepted but is a no-op
`_validate_rule` accepts it; `decide()` neither short-circuits on it nor suppresses later `alert` or
`block` matches. Anyone writing an allowlist rule gets silent surprise. Either implement allowlist
semantics or reject the action at load time with a clear error.

### 4. `severity_gte` cannot fire on events this package produces
It compares a top-level `event["severity"]`, which `new_event` never sets and which is not in
`EVENT_KEYS`. Documented in the module docstring, but it remains a matcher that only works for custom
pipelines — a trap for community rule authors.

### 5. Declared-but-never-emitted event types
`llm_call` and `policy_decision` are in `EVENT_TYPES`, and `llm_call` is mapped in `otel._OPERATION`,
but nothing constructs either. Either emit them or mark them reserved.

### 6. `aileron verify` mishandles unusable paths — wrong verdict, or an uncaught traceback
Two related defects:

- **Missing file** → `chainlog.verify` returns `ok=False` for a nonexistent path, so the CLI takes the
  tamper branch and prints `TAMPERED at seq None`, exit 2.
  `test_cli.py::test_verify_missing_log_nonzero` only asserts non-zero and its comment accepts either
  code, so the misleading message is unpinned. A tamper verdict is a serious claim and should not be
  produced by a typo.
- **Directory or unreadable file** → `os.path.exists` passes, then the unguarded `open(path, "rb")`
  raises `IsADirectoryError` or `PermissionError`. Both are `OSError`, which `cli.main()` does not
  catch (it catches `FileNotFoundError`, `ValueError`, `KeyError`, `ImportError`), so
  `aileron verify <dir>` exits with a traceback.

This also qualifies the "verify never raises" property stated elsewhere: it is total over file
*content*, not over the file handle. Worth fixing precisely because verification is the one operation
users are told to trust — exit 1 with a distinct "cannot read" message, and catch `OSError` in `main()`.

### 7. Supply-chain gaps
Runtime dependencies and all GitHub Actions are unpinned; there is no lock file, no SBOM, and no
dependency-scanning job. The security-baseline extension's SECURITY-10 would flag this, and it is
awkward specifically for a tool selling verifiable provenance.

### 8. `sdk.default_log()` is a process-global singleton
`AILERON_LOG` is resolved once and cached in `_default_log`; later changes have no effect. The
module-level `_FALLBACK_SESSION_ID` also means every untracked-session call in a process shares one
`session_id`. Both are defensible for convenience but are unobvious and untested.

### 9. Stale artifacts in the working tree
`benchmarks/` contains nothing but a `__pycache__` for a `bench_proxy` module whose source moved to
`scripts/benchmark.py` in `b4b6b07`. `dist/`, `src/aileron.egg-info/`, and `.pytest_cache/` are also
present (gitignored). `benchmarks/` should be deleted to avoid implying a second benchmark harness.

### 10. `rate-spike-note.md` is bundled but never delivered
`aileron init` globs `*.yml` only, so the note explaining rules versus detection never reaches the
user's seeded `rules/` directory — the one place it would be read.

## Patterns and Anti-patterns

**Good patterns**
- Canonical serialisation owned by a single import-free leaf module.
- Bytes-on-disk-are-authoritative verification, catching forgeries that merely hash correctly.
- Poisoned-sentinel chain break, so a forged tail cannot re-sync to genesis.
- Fail-closed mediation throughout the proxy, including a re-check immediately before forwarding.
- Re-serialise-don't-relay on both directions of the wire.
- Enforcement decoupled from persistence, so privacy defaults do not weaken policy.
- A verifier written to be total, treating crash-on-input as a security bug.
- Checkpoints chained to each other, not just to the log.
- Key files created with restrictive modes and `O_NOFOLLOW` in a single `os.open`.
- Lenient reader, strict authority — an explicitly documented split in `chainlog`.
- Benchmarks that report a differenced measurement plus the absolute baseline, so the subtraction can
  be checked, with CI enforcing the result and a path filter that keeps the guard honest.

**Anti-patterns / smells**
- `cli.py` as a god module, with dispatch logic split between `_DISPATCH` and a special case in `main()`.
- `proxy.py` at 428 lines mixing framing, policy dispatch, subprocess lifecycle, and threading in one
  module — justified by cohesion, but it is where a future split would go if it grows again.
- Duck-typed sink (`log: Any`) in the one component that must never lose a record.
- A dead matcher (`severity_gte`) and a no-op action (`allow`) both accepted by the validator.
- Documentation asserting authority (`SPEC.md`) while trailing the code.
- Advertised typing (`py.typed`) with no type checker in CI.

## Recommended Priorities

1. Bring `SPEC.md` back in line with the code, or demote it explicitly to a design sketch and make
   `aidlc-docs/inception/reverse-engineering/` the authoritative description.
2. Add tests for the seven untested invariants, starting with `_canonical_wire` in both directions
   and the `record_failed` refusal path.
3. Fix `verify` on unusable paths: exit 1 with a distinct message for a missing file, and catch
   `OSError` in `main()` so a directory or unreadable file cannot produce a traceback.
4. Resolve `action: allow` and `severity_gte` — implement or reject, but do not leave them silently inert.
5. Add ruff and mypy to CI as non-negotiable gates before the codebase grows further; the style is
   already consistent, so adoption cost is near zero now and rises with every module.
6. Pin GitHub Actions to commit SHAs and add dependency scanning plus an SBOM, which also pre-satisfies
   the security-baseline extension.
7. Split `cli.py` before parallel work begins — at minimum move `_cmd_demo` into its own module.
