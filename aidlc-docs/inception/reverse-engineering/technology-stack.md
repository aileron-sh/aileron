# Technology Stack

Generated by AI-DLC Reverse Engineering against git `6c09efd` (Aileron 0.1.3), 2026-08-12.

## Programming Languages

- **Python** — `requires-python = ">=3.10"`; CI proves 3.10, 3.11, 3.12, 3.13 on Ubuntu and macOS.
  Used for the entire package, tests, and the benchmark harness. Type hints throughout, with
  `py.typed` shipped so downstream users get the annotations (PEP 561).
- **Shell (bash)** — one file, `examples/mcp_proxy_demo.sh`, an end-to-end demonstration.
- **YAML** — policy rule format (`rules/examples/*.yml`) and GitHub Actions workflows.

No compiled extensions, no vendored C, no build step beyond a pure-Python wheel.

## Frameworks

None, deliberately. Aileron takes no dependency on LangChain, CrewAI, or any agent framework:
`@track` is a plain decorator and `track_agent` accepts a free-form `framework=` label, so
integration is by convention rather than by import. The `examples/langchain_tool_tracking.py` demo
duck-types the framework interface rather than importing any framework — though note that its own
docstring's "stdlib-only" claim is inaccurate: it imports `aileron.policy`, which imports `yaml` at
module scope, so PyYAML is required to run it.

The one protocol Aileron implements against is the **Model Context Protocol** over JSON-RPC 2.0
stdio, and it is implemented directly (both newline-delimited and `Content-Length` framing) rather
than through an SDK.

## Runtime Dependencies

- **PyYAML** — unpinned. Parses policy rule files in `policy._load_rule_file`.
- **cryptography** — unpinned. Ed25519 key generation, signing, and verification in `signing.py`.

Two runtime dependencies for a security tool is a deliberate posture, and it is worth keeping that
way: every added dependency is supply-chain surface in a package whose entire value is that its
output can be trusted.

## Infrastructure

- **None deployed.** No cloud services, containers, databases, or infrastructure-as-code in the
  repository. Persistence is local files: `*.chain.jsonl`, `*.chain.jsonl.checkpoints.jsonl`, an
  Ed25519 keypair, and an optional JSON baseline state file.
- **Distribution**: PyPI, as a pure-Python wheel plus sdist.

## Build Tools

- **setuptools** with PEP 621 metadata in `pyproject.toml`; `src/` layout; no `setup.py`.
- **build** (`python -m build`) — produces the wheel and sdist in `release.yml`.
- **twine** — `twine check dist/*` before publishing.
- **pypa/gh-action-pypi-publish@release/v1** — publishes with `environment: pypi` and
  `permissions: id-token: write`. Trusted publishing over OIDC, no stored API tokens.
- **pip** — `pip install -e ".[dev]"` in CI.

## Testing Tools

- **pytest** (dev extra, unpinned) — the whole suite. CI runs `python -m pytest tests/ -q`.
  117 test functions across 10 modules; roughly 122 collected items once
  `test_policy.py::test_load_rules_error_cases` expands its six parametrisations.
- **No coverage tool, no linter, no formatter, and no type checker is configured.** There is no
  `.flake8`, `ruff.toml`, `mypy.ini`, or `[tool.*]` lint section, and no pre-commit config. The code
  is nonetheless consistently formatted and annotated. This is a gap worth closing given that the
  package ships `py.typed`: users receive type promises that CI does not check.
- **Custom benchmark harness** — `scripts/benchmark.py`, stdlib-only. Drives an identical MCP child
  directly and through the proxy, subtracts to isolate proxy cost, discards 200 warmup calls, then
  measures 2,000 sequential calls per configuration and reports mean, median, p95, and p99.

## CI/CD

- **GitHub Actions**, three workflows:
  - `ci.yml` — 8-job matrix (2 OS × 4 Python), `fail-fast: false`, `permissions: contents: read`.
  - `benchmark.yml` — path-filtered to `src/aileron/**`, the benchmark script and baseline,
    `pyproject.toml`, and itself, so a docs-only change never triggers it and a run that does
    trigger is allowed to fail. Threshold is 2.0× the baseline median added overhead per payload
    size, with a retry-once rule: one trip is a warning, two consecutive trips fail the job. Writes a
    step summary and uploads results as artifacts.
  - `release.yml` — `release: [published]` plus manual dispatch; test → build → publish.

## Security-Relevant Toolchain Notes

- Key material is written with `os.open(..., O_WRONLY|O_CREAT|O_TRUNC|O_NOFOLLOW)` and mode `0o600`
  at creation time, so there is no window in which the private key is world-readable and no symlink
  can redirect the write.
- The package makes **no network calls at all** — no telemetry, no update check, no phone-home. This
  is asserted in the README as a product guarantee and holds in the code.
- Dependencies are **unpinned** in `pyproject.toml`. Reasonable for a library (it avoids forcing
  resolution conflicts on consumers) but it means CI results are not reproducible against a fixed
  dependency set, and there is no lock file, SBOM, or dependency-scanning job. The security-baseline
  extension's supply-chain rule (SECURITY-10) would flag this.
